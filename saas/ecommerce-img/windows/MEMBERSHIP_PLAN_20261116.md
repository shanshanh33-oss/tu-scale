# TU Scale 会员系统方案草案（2026-11-16）

状态：**规划，未实现、未定价、未启用支付**。与 `COMMERCIAL_READINESS_20261116.md` 配套。现有 React/Vite 前端、Cloudflare Pages Functions/KV、匿名统计和本地图片处理保持原样；仓库目前没有普通用户账号、订单、支付或会员权益接口（见 `PROJECT.md` 与 `functions/api/`）。不把管理员看板 Token 当作会员身份。

## 产品边界

| 层级 | 规划权益 | 当前状态 |
| --- | --- | --- |
| 免费访客 | 现有本地放大、压缩、商品图、裁切、批量、导出等能力继续无需登录；图片默认留在浏览器 | 已有产品功能，不因会员系统回收 |
| 免费账号 | 可选登录以管理未来订单、授权设备和客户支持；是否提供跨设备设置须另行确认 | 未实现；不应为本地处理强制注册 |
| 按次包 | 将来仅对**服务器承担成本且已验证价值**的任务预购额度；展示单次扣减、有效期和余额 | 未定产品/价格/额度，不可出售 |
| 会员 | 将来包含明确数量的云端任务、优先队列或协作服务；超额规则和服务承诺单独列明 | 未定产品/价格/额度，不可宣传为现有能力 |

当前候选放大模型没有证明比 waifu2x 更好，不能作为付费权益。任何云端处理都应在用户明确选择后才上传原图，说明处理地点、保存期限和删除方式；匿名免费路径不应受影响。

## 最小系统边界与数据

1. **身份**：账号服务提供注册/登录、邮箱验证、会话续期、退出、找回、注销；可选登录方式和供应商待决定。浏览器会话使用安全 Cookie 或等效机制，服务端鉴权；不在前端包中放支付或服务端密钥。账号和匿名浏览器历史不自动关联。
2. **目录与权益**：服务端发布版本化的套餐目录，明确币种、账期、可用任务、有效期、结转、超额、取消与退款口径。前端只显示服务端返回的有效权益，不能自报会员状态。免费本地工具不走额度检查。
3. **订单与支付**：订单包含服务器生成的价格快照、状态与幂等键；仅验证过签名和金额的支付回调才能从 `pending` 变成 `paid` 并授予权益。重复、乱序或延迟回调不能重复开通。支付平台、结算主体与方式尚待批准。
4. **权益账本**：用可事务化的持久存储记录 `grant / reserve / commit / release / expire / refund`，每笔带订单或任务幂等标识。云任务入队先预占，成功才扣减，失败/取消释放；并发下不能透支，退款要可追溯地撤销未用权益。Cloudflare KV 现用于统计/反馈，不应直接承担支付交易与原子额度账本。
5. **任务**：最小记录为任务 ID、用户 ID、产品类型、状态、计量单位、创建/完成时间和错误码。默认不记录图片内容、原文件名或图片哈希；云端图片采用单独的短期临时存储、访问控制和到期清理，具体保留期需要用户与法务决定。
6. **运维**：管理端需严格权限、审计日志、人工退款/补单双重校验、日对账、成本上限及异常告警。只收集提供服务所需数据；不得沿用公开统计接口或扩大当前埋点来跟踪个人。

建议的逻辑实体：`users`、`sessions`、`plan_catalog_versions`、`orders`、`payment_events`、`subscriptions`、`entitlement_ledger`、`usage_jobs`、`audit_events`。这是设计清单，**没有在仓库或生产环境建表**。实际存储和部署选择要与腾讯云/现有 Cloudflare 方案、事务需求、区域合规和费用一起评审。

## 关键状态与失败处理

| 场景 | 必须满足的行为 |
| --- | --- |
| 支付成功回调重复到达 | 订单只确认一次，权益只授予一次；回调原文和验签结果留服务端审计，不进浏览器日志 |
| 客户端显示成功但回调未确认 | 仍显示待确认，不提前开放付费权益；提供查询和客服处理入口 |
| 云任务失败、超时或用户取消 | 预占额度释放或按已明示规则结算；不能静默扣次 |
| 订阅取消 | 告知权益终止时间与自动续费状态；不改变免费本地功能 |
| 升降级、退款、拒付 | 按价格快照和账本作可追踪调整，防止重复退款或负余额；例外进入人工复核 |
| 服务不可用或成本阈值触发 | 暂停新付费云任务并保留订单/账本一致性；匿名本地工具继续可用 |

## 分阶段实施与验收门槛

1. **产品确认**：确定第一个实际付费能力、目标地区、价格与额度、支付渠道、会员是否自动续费、取消/退款口径。此阶段只做用户研究与成本测量，不改支付配置。
2. **离线原型**：在隔离开发环境实现账号和只读权益展示、套餐目录、幂等订单状态机和模拟支付回调；使用虚构数据，测试重复回调、并发扣额、退款与故障恢复。不得接真实收款。
3. **小范围试点**：合规材料与支付测试账户就绪后，先让受邀用户试用明确告知的云任务；测成功率、P95 延迟、每任务真实成本、投诉/退款率和画质盲评偏好。可暂停，不能自动扩大额度。
4. **生产放行**：代码审查、安全/隐私审查、对账和灾难恢复演练完成，并经用户明确批准生产价格、密钥、域名、部署与 `main` 变更后才上线。

当前最重要的未决选择：**第一项值得收费的云能力是什么**。50 张单轮盲评没有证明候选模型显著优于现有免费模型，故会员系统可以先设计与模拟，但不能据此开始真实收费。
